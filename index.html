Koordinatenvergleich

Vergleicht mehrere Koordinatensätze pro Punkt miteinander (z.B. eigene Messung, DWG-Werte des Kunden, weitere Quellen) und berechnet Mittelwert sowie Spannweite. Reine Berechnung, keine externe Abfrage.

Erwartetes Format: Name;Messreihe;Ost;Nord;Hoehe (Kopfzeile erforderlich, Hoehe optional, Trennzeichen , oder ;). Jede Zeile ist ein Wert einer Messreihe fuer einen Punkt.

Kartenansicht

Zeigt die Punkte aus der Höhen-Prüfung auf einer Karte (OpenStreetMap). Die Marker-Farbe folgt derselben Abweichungs-Einordnung wie in der Tabelle. Punkte aus dem Koordinatenvergleich werden hier nicht dargestellt.

Einstellungen

Persönliche Einstellungen für dieses Tool – gelten nur in diesem Browser auf diesem Gerät.

Oberfläche Wirkt sich nur auf Anzeige/Bedienung dieses Tools aus - keine externen Dienste beteiligt.
Helles Design (Light Mode)
Stellt das Tool auf eine helle Farbgebung um, statt des dunklen Standard-Designs. Wirkt sich nur auf dieses Gerät/diesen Browser aus – jede Person kann das für sich unabhängig wählen.
Projektfeld in der Kopfzeile
Zeigt das Eingabefeld "Projekt / Bezeichnung" oben im Tool, auf allen Reitern gleichzeitig (Höhe, Vergleich, Karte). Wird für PDF-Kopfzeile, CSV- und GCP-Dateinamen verwendet.
PDF-/CSV-Export-Buttons auch auf der Kartenansicht
Die Export-Buttons ("🖨️ Prüfdokument als PDF" / "⬇️ Als CSV") beziehen sich auf die Höhen-Prüfung und sind auf dem Karte-Reiter standardmäßig ausgeblendet, um dort nicht abzulenken. Hier lassen sie sich bei Bedarf wieder einblenden.
Verbindungen & API-Keys Zugangsdaten zu externen Diensten - werden ausschließlich lokal in diesem Browser gespeichert und nur direkt an den jeweiligen Anbieter gesendet, nie in diese Datei oder an uns.

Ohne Key: kostenlose OSM-Standardkacheln. Der Key wird ausschließlich lokal in diesem Browser gespeichert (nicht in dieser Datei, nicht an uns) und nur direkt an MapTiler gesendet.

Team-Synchronisierung (Echtzeit)
Optional: Verbindet die Höhen-Prüfung mit einer gemeinsamen Datenbank (Supabase), sodass alle im Team dieselben Punkte in Echtzeit sehen. Anders als der MapTiler-Key ist dieser Zugang für das ganze Team gedacht – alle tragen dieselbe URL und denselben Key ein.

Zugang wird lokal in diesem Browser gespeichert und ausschließlich direkt an Supabase gesendet (nicht in dieser Datei, nicht an uns). Betrifft die Höhen-Prüfung sowie – sofern die untenstehende Tabelle angelegt ist – auch die Einsatzübersicht; nicht den Koordinatenvergleich.

Für die Einsatzübersicht (Reiter "Einsatzübersicht") müssen in eurem Supabase-Projekt einmalig zwei zusätzliche Tabellen angelegt werden (SQL-Editor in Supabase, analog zur bestehenden "punkte"-Tabelle):
create table if not exists public.einsaetze ( id uuid primary key default gen_random_uuid(), team text, adresse text, lat double precision, lon double precision, datum date, notiz text, aktualisiert_am timestamptz default now() ); alter table public.einsaetze enable row level security; create policy "team_lesen_schreiben" on public.einsaetze for all using (true) with check (true); create table if not exists public.teams ( id uuid primary key default gen_random_uuid(), name text not null, farbe text not null, aktualisiert_am timestamptz default now() ); alter table public.teams enable row level security; create policy "team_lesen_schreiben" on public.teams for all using (true) with check (true);

Für die Geräte-Übersicht unter "Zugangssperre" (weiter unten) wird optional eine dritte Tabelle genutzt – ohne sie funktioniert die Passwort-Hürde selbst ganz normal, nur die Liste der bekannten Geräte bleibt dann leer:
create table if not exists public.geraete ( id text primary key, name text, erstellt_am timestamptz default now(), letzter_zugriff timestamptz default now() ); alter table public.geraete enable row level security; create policy "team_lesen_schreiben" on public.geraete for all using (true) with check (true);

Zugangssperre – bekannte Geräte
Diese Übersicht zeigt, welche Geräte die Passwort-Hürde beim Öffnen des Tools (siehe Hinweis dort) schon einmal erfolgreich passiert haben – erkennbar am selbst gewählten Gerätenamen. Wichtig: Das ist keine echte Zugriffskontrolle, sondern nur zur Übersicht gedacht. Da alle dasselbe Passwort verwenden, lässt sich ein einzelnes Gerät hier nicht gezielt sperren – dafür müsste das gemeinsame Passwort geändert werden (Rücksprache halten). Nur sichtbar, solange die Tabelle "geraete" angelegt ist (siehe SQL oben) und die Team-Synchronisierung verbunden ist.
